# 第三步 · 无包装粗样（P2）取证执行规程（抽帧 / 画面声音一起核对）

> 配套 `assets/prompt-p2-roughcut.md` 与 `references/p2-field-contract.md`。
> 本规程只服务 P2 粗样的画面/音频核验，不重新选段；工具能力以当前环境真实机器合同为准，未实测项标注待验证。

## 1. 目标

提高精彩片段（表情、肢体动作、走位、现场反应、语调起伏）的召回率，**不依赖全片均匀加密抽帧**：先找锚点，再定点取证，候选段加密，主干段低档，音画一起合诊。

## 2. 候选锚点清单（三来源并集）

汇总三类时间点，按时间排序、去重，形成待核验候选清单：

| 锚点来源 | 找什么 | 生成方式 |
|---|---|---|
| 语义锚点 | 金句、反问、点名人物、案例段、明显停顿句 | 取自 P1 结构单保留段与转写稿；金句/反问/点名/案例/停顿句登记时间码 |
| 音频锚点 | 笑声、掌声、惊呼、语调陡升、重音、突然停顿 | 先在候选段用带音频理解回填时间码；独立音频事件检测工具待环境核实后接入 |
| 画面锚点 | 镜头切换、景别变化、动作幅度变化 | 场景变化抽帧兜底，或视频理解分镜返回的动作/走位点 |

- 除 P1 已标出的需核验段外，反向扫主干中转写平淡但有动作/反应线索的点（设问后停顿、案例前后、语气转强），补入清单。
- 首批锚点取自本批 D1 定位与 P1 结构单保留段；换素材时按上表三来源重新生成时间点，不沿用上一批次的锚点清单。

## 3. 取帧方式选型

| 场景 | 取帧方式 | 参数口径（以工具机器合同为准） |
|---|---|---|
| 已知锚点定点取证 | 按指定时间点抽帧 | 定点列表传秒级时间点，最多 3 位小数、上限 1000 点；每个候选点取起势 / 峰值 / 回落三帧（t−0.8s、t、t+0.8s，容差 ±0.5–1s） |
| 镜头/画面变化兜底 | 场景变化抽帧 | 场景变化阈值默认 0.1；阈值越小越敏感、出帧越多，按废帧量回调 |
| 普通主干粗扫 | 按时间间隔抽帧 | 间隔默认 1 秒；主干段用低档，只做通读衔接核对 |
| 连续动作（扮丑、走位、表情转变） | 优先送 0.5–1 秒短片段给理解模型 | 不只取单张静态帧；静态帧只补姿态证据 |

- 异步任务先取 task_id，再轮询终态结果；截图链接有效期 24 小时，核验后及时留存结论。
- 批量送理解时可用雪碧图汇总；按长边缩放控制图片体积。

## 4. 音画合诊配置

候选段送视频理解时：

- 场景设为创作剪辑，要求输出带时间戳的分镜/片段描述；
- 开启音频分析，画面与声音一起判，避免情绪反应只靠画面猜；对象参数的内联 JSON、`@文件`、`file:///` 协议是否被识别、音频开关参数名与取值，均以当前 `--schema` 机器合同为准（早期实测部分对象参数不被识别）；当前通用做法是在理解指令中写入"笑声/声音/语气"等音频关键词触发音频多模态链路，显式音频开关待后续按合同核实；
- 档位：候选高点段用质量档，普通主干粗扫用均衡或经济档；
- 抽帧帧率按候选段动作密度调整，连续动作段适当加密；
- 理解指令必须显式要求逐时间码输出标签：表情、肢体动作、走位、语气起伏、现场反应（笑声/掌声/附和），不只概括"讲了什么"。
- **批量并行提交**：候选小片一次备齐后批量提交，任务并行轮询，不等上一段返回再送下一段；单段失败、超时或结果不足不阻塞其余段，按锚点分别回写结论；并行提交仍逐段套用上述场景、音频关键词与档位配置，不在一条任务里混装多个候选段。

## 5. 候选清单与回写字段

| 字段 | 说明 |
|---|---|
| 候选时间码 | `MM:SS–MM:SS`，以主素材为准 |
| 锚点来源 | 语义 / 音频 / 画面（可多选） |
| 关联结构单序号 | 对应 P1 结构单成片序号；反向补扫段标"反向回查" |
| 证据类别 | 需画面核验 / 需音频核验 |
| 取证方式 | 定点抽帧 / 场景变化抽帧 / 短片段理解 / 带音频理解 / 上下文比对 |
| 时间码基准 | 母带 ASR / 小片相对秒 / 云端相对秒；相对秒加回区间起点换算母带秒后入执行单 |
| 核验结论 | 动作/表情/反应/语调是否成立，附时间码与依据 |
| 处置 | 保留为依据 / 降格留痕 / 待核 |

- 佐证成立：保留为对应笑点、互动或情绪高点依据；
- 无法佐证：降格为不作为依据，回写结构单备注，不做强化剪辑；
- 取证失败或模型无法确认：保守降格，不硬判笑点；存疑段占位保留挂待核。

## 6. 分层与耗时控制

1. 先用语义锚点 + 主干粗扫定位候选区间；
2. 只对候选段加密定点取帧或送短片段理解；
3. 普通主干段低档通读，不逐帧密采；
4. 定位、核验、拼接分项记录 AI 耗时；人工确认等待不计入。

## 7. 待验证能力（实跑时如实标注，不预设结论）

- 高光拆条模型面向短剧/游戏，且要求画面下半部有清晰烧录中文字幕、音频有清晰中文对话；原片自带烧录字幕条时，字幕清晰度是否满足模型门槛待实测，仅作待实测候选，不作默认依赖；P3 须先决定沿用、保留或擦除原字幕，不能直接压新字幕。
- 独立音频事件检测（笑声/掌声/语调点自动打点）走哪个音频工具，待核实；当前先以带音频理解回填。
- 锚定策略对情绪高点的实际召回率、各取帧方式的废帧量与耗时，均以本片实跑结果为准。

## 8. 首轮实跑能力边界（实跑小片、经济档）

- 音频事件可用：集体笑声、附和发言、语气突增与音量峰值可标注；附和/笑声置信偏低，需二次确认，不凭单次标注保留为高点。
- 表情/神态召回弱：模型自述无法确证面部表情，动作精确顶点时间戳返回 null；表情丰富度不能只靠该模型判断，峰值帧须定点抽帧补。
- 动作区间可用、顶点不足：能给出动作表演区间（起/止秒），但纯动作段常落在 ASR 句点之外；只锚定转写句时间码抽帧会取到叙述句帧，连续动作段须另取起势/峰值/回落三帧或送短片段理解。
- 输出时间码为相对片段秒，拼接前须换算回主素材时间码；每条证据登记链路基准（母带 ASR / 小片相对秒 / 云端相对秒），相对秒加回区间起点得母带秒。同一锚点不同链路时间码错位时，并列两来源回区间交叉复核；仍不一致挂待核，不按单一来源写死截取码。

## 9. 本地拼接执行约束（环境具备本地拼接能力时）

1. 参数统一：逐段裁成统一分辨率、帧率、音频参数的段文件后再合并；编码参数不一致时先重编码统一，不直接流复制，避免段间时间戳错位、黑屏或音画异常。
2. 段文件校验：每段落盘后确认非空、可解码；0 字节、损坏或解码报错的段剔除并重裁，不带入成片。
3. 合并后自检：整段解码检测无错误；抽查段间衔接帧非黑屏、人物画面正常；成片时长与结构单净时长合计复核一致；段数一一对应。
4. 预览口径：本地降规格（如降分辨率、调高 CRF）只用于人工确认环节审看顺序与衔接，不代表成片画质；产物须标注「预览」状态，正式粗样画质口径在第四步（P3）前定稿。
5. 能力边界：拼接走本地还是云端、各工具的输入大小与时长限制，以当前环境实测机器合同为准；未实测的整段上传、云端拼接与整段理解能力标待验证，不预设可用。
6. 代理粗剪路径（仅当预计多轮修改、经人工确认环节选择启用）：先生成一条低清代理母带——恒定帧率、时间码直通主素材、音频保留原轨不降码；代理上只做结构、顺序、衔接判断与云端理解抽帧；结构单/拼接清单确认后回母带按同一时间码实出高画质段；代理分辨率档位与编码提速幅度未经实测前不写死、不承诺比例；表情动作、字幕清晰度终审回母带帧核验。
